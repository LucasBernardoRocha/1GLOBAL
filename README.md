# Devices API

A small REST API for managing devices, built with Go, PostgreSQL and the
standard library. The project is container-first: the API, the database and the
Go toolchain all run in Docker, so no local Go installation is required.

## Features

- Create, list, get, update and delete devices.
- Filter listings by brand and/or state.
- Server-generated, immutable creation timestamp.
- Domain rules for devices that are in use.
- Server-Sent Events (SSE) stream for committed state changes.
- OpenAPI 3 specification and offline Swagger UI served by the application.
- Structured logs, request IDs, health/readiness probes and graceful shutdown.
- PostgreSQL persistence with embedded migrations and row-level locking.
- Unit, HTTP, broker and PostgreSQL integration tests.

## Stack

| Concern | Choice |
|---|---|
| Language | Go 1.23+ |
| HTTP | `net/http` with `ServeMux` patterns |

| API docs | OpenAPI 3.0 |

## Quick start

Requirements: Docker with Compose v2.

```bash
docker compose up --build
```

The API is available at `http://localhost:8080`:

- Swagger UI: [http://localhost:8080/docs/](http://localhost:8080/docs/)
- OpenAPI spec: `http://localhost:8080/openapi.yaml`
- Liveness: `http://localhost:8080/healthz`
- Readiness: `http://localhost:8080/readyz`

To stop the stack and remove the database volume:

```bash
docker compose down -v
```

## API

| Method | Path | Description |
|---|---|---|
| `POST` | `/v1/devices` | Create a device |
| `GET` | `/v1/devices?brand=&state=` | List devices, optionally filtered |
| `GET` | `/v1/devices/{id}` | Get a device by ID |
| `PATCH` | `/v1/devices/{id}` | Partially or fully update mutable fields |
| `DELETE` | `/v1/devices/{id}` | Delete a device |
| `GET` | `/v1/devices/events` | SSE stream of state changes |
| `GET` | `/healthz` | Liveness probe |
| `GET` | `/readyz` | Readiness probe |
| `GET` | `/docs/` | Interactive Swagger UI |
| `GET` | `/openapi.yaml` | OpenAPI specification |

The full contract, schemas, examples and status codes are in
[`api/openapi.yaml`](api/openapi.yaml). Open
[http://localhost:8080/docs/](http://localhost:8080/docs/) for the interactive
version: endpoints can be explored and executed directly from the browser with
**Try it out**. The UI is embedded in the binary, so it also works without
internet access.

### Create a device

```bash
curl -s -X POST http://localhost:8080/v1/devices \
  -H 'Content-Type: application/json' \
  -d '{"name":"iPhone 15","brand":"Apple"}'
```

```json
{
  "id": "3f1c7b1e-7d9a-4c1b-9f2e-6a4d8c0b1e23",
  "name": "iPhone 15",
  "brand": "Apple",
  "state": "available",
  "created_at": "2026-11-05T10:07:00Z"
}
```

`state` is optional and defaults to `available`. `id` and `created_at` are
generated by the server.

### List devices

```bash
curl -s http://localhost:8080/v1/devices
curl -s 'http://localhost:8080/v1/devices?brand=Apple'
curl -s 'http://localhost:8080/v1/devices?state=in-use'
curl -s 'http://localhost:8080/v1/devices?brand=Apple&state=available'
```

Brand matching is exact. An unknown `state` returns `400`.

### Get a device

```bash
curl -s http://localhost:8080/v1/devices/<device-id>
```

### Update a device

`PATCH` accepts `name`, `brand` and `state`. Omitted fields stay unchanged.

```bash
curl -s -X PATCH http://localhost:8080/v1/devices/<device-id> \
  -H 'Content-Type: application/json' \
  -d '{"name":"iPhone 15 Pro","state":"in-use"}'
```

`created_at` is immutable. Sending it returns:

```json
{
  "error": {
    "code": "immutable_field",
    "message": "created_at cannot be updated"
  }
}
```

While a device is `in-use`, changing `name` or `brand` returns `409`; changing
only `state` is allowed.

### Delete a device

```bash
curl -s -X DELETE http://localhost:8080/v1/devices/<device-id>
```

A successful delete returns `204 No Content`. A device in the `in-use` state
returns `409` and is not removed.

### Stream state changes

Open a stream in one terminal:

```bash
curl -N http://localhost:8080/v1/devices/events
```

Then change a device state in another:

```bash
curl -s -X PATCH http://localhost:8080/v1/devices/<device-id> \
  -H 'Content-Type: application/json' \
  -d '{"state":"in-use"}'
```

The stream receives:

```text
event: device.state_changed
data: {"device_id":"3f1c7b1e-7d9a-4c1b-9f2e-6a4d8c0b1e23","previous_state":"available","new_state":"in-use","changed_at":"2026-11-05T12:00:00Z"}
```

The event is published only after the database transaction commits. Events are
not replayed after a disconnect or restart; see the design decisions for the
production path.

## Domain rules

- `state` is one of `available`, `in-use` or `inactive`.
- `created_at` is generated by the server and cannot be changed.
- A device in `in-use` cannot have `name` or `brand` changed.
- A device in `in-use` cannot be deleted.
- A state change to the same state is a successful no-op and emits no event.
- State changes are unrestricted in direction; the challenge does not define a
  state machine.
- Notifications contain the device ID, previous state, new state and timestamp.

## Error format

Errors use a consistent JSON envelope:

```json
{
  "error": {
    "code": "validation_error",
    "message": "name: is required"
  }
}
```

| Status | When |
|---|---|
| `400` | Malformed JSON, unknown field, invalid UUID, invalid state, invalid name/brand, attempt to update `created_at` |
| `404` | Device not found |
| `409` | Operation blocked because the device is in `in-use` |
| `500` | Unexpected server error |

## Configuration

| Variable | Required | Default | Description |
|---|---|---|---|
| `DATABASE_URL` | yes | — | PostgreSQL connection string |
| `PORT` | no | `8080` | HTTP listen port |
| `LOG_LEVEL` | no | `info` | `debug`, `info`, `warn` or `error` |
| `SHUTDOWN_TIMEOUT` | no | `10s` | Graceful shutdown budget |

The Compose file sets `DATABASE_URL` automatically. Optional overrides are
documented in [`.env.example`](.env.example). The container port stays fixed at
`8080` in Compose; `PORT` is useful when running the binary outside Compose.

## Development

All Go commands run through Docker:

```bash
./scripts/go.sh go test ./...
./scripts/go.sh go vet ./...
./scripts/go.sh go build ./...
```

Or use the Make targets:

```bash
make help
make fmt
make vet
make test              # unit and HTTP tests
make test-race         # race detector
make test-integration  # all tests against a disposable PostgreSQL
make build             # API container image
make up                # API + PostgreSQL
make down              # stop and remove volumes
```

Integration tests are opt-in: they run only when `TEST_DATABASE_URL` is set.
`make test-integration` starts a temporary PostgreSQL service and runs the suite
inside the Compose network.

## Design decisions

The rationale for PostgreSQL, SSE, PATCH-only updates, no authentication and no
pagination is documented in [`docs/decisions.md`](docs/decisions.md), including
trade-offs and the production path for each choice.

## Known limitations and next steps

- No authentication or authorization; production requires OAuth2/mTLS/API keys.
- No pagination; production should add cursor pagination and a max page size.
- The in-process broker does not replay events or share them across replicas.
- No rate limiting, metrics or distributed tracing yet.
- No Kubernetes manifests or dedicated migration job.
- No idempotency keys for mutating requests.

These are deliberate scope choices for the challenge, not hidden behavior.
